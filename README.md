# Failure-Boundary Profiles: Scenario Families

Certified scenario families for measuring failure-boundary profiles of autonomous driving agents in CARLA and of a warehouse robot in Isaac Sim. This repository is the public artifact of the paper "Beyond Driving Scores: Failure-Boundary Profiles" (in preparation, arXiv fall 2026) by Social Chaos Lab.

Instead of a single score, each family sweeps one physical factor of a hard scenario (for example, how far a fallen obstacle intrudes into the driving corridor) across a set of measured, validated variants. Running an agent across a family locates where its behavior flips, and repeating across traffic seeds turns that location into a distribution rather than an anecdote.

This repository bundles everything needed to run the driving families: the scenario data **and** the [Fail2Drive](https://github.com/autonomousvision/fail2drive) evaluation harness they run under, vendored with our two fork patches already applied. See [Bundled harness](#bundled-harness).

Three things live here, and the root mixes them; this is which is which.

| Path | What it is |

| `scl/` | the measurement chain that produced the paper's numbers, a generated byte-identical export of the private pipeline's measurement layer: scorers, certifiers, pooling, the figure tools and the one command that renders every figure, table and number of the paper, with the instruments, manifests, records and figure specs they read; `PUBLIC_EXPORT.json` (every file by hash, the private commit) and `PUBLIC_PROOF.json` (the campaigns re-scored from this tree). ## Scenario families

The families live under [`scl_families/`](scl_families), one directory per family, the profiling counterpart to the harness's own `fail2drive_split/`. The directory is GENERATED by the private pipeline's export from the family manifests under [`scl/`](scl); its [README](scl_families/README.md) holds the family table (swept factor, range, variants, town, realization) and `scl_families/SHA256SUMS` verifies every file: `cd scl_families && sha256sum -c SHA256SUMS`.

The static-obstacle families run in CARLA Town13 and the two oncoming-flow families in CARLA Town03, all under fixed clear weather; each variant is a standard leaderboard-format route XML. The three warehouse families run in Isaac Sim 5.1; a variant is a stage the SCL runner compiles from the family manifest, and the runner is not released, so those families are published as manifests with catalogs. The paper's family numbers map to the directories as follows:

| Paper | Family |
|---|---|
| 1 Charger gauntlet | `fm_004_threshold_sweep` |
| 2 Machine intrusion | `fm_001_intrusion_sweep` |
| 3 Corridor width | `fm_002_corridor_pincer` |
| 4 Identity ladder | `fm_003_asset_swap` |
| 5 Cluttered intrusion | `fm_005_hero` |
| 6 Oncoming flow speed | `fm_011_flow_speed_sweep` |
| 7 Oncoming flow spacing | `fm_012_source_dist_interval_sweep` |
| 8 Warehouse: slab pincer | `fm_isaac_001` |
| 9 Warehouse: floor stock | `fm_isaac_003` |
| 10 Warehouse: composed stacks | `fm_isaac_004` |

Each driving family directory - for example `scl_families/fm_001_intrusion_sweep/` - contains:

- `routes/` - one route XML per accepted variant, byte-identical to the files used in our measurement campaigns (the same files sit under `scl/artifacts/examples/backend_outputs/`, where the scoring chain reads them).
- `variants.csv` - the variant catalog: target factor value, and the measured, in-simulator verified geometry of the realized scene (free corridor width, route intrusion, required lateral deviation, closest approach distance). Generated from the family manifest under `scl/artifacts/examples/solved_families/`; `scl/PUBLIC_EXPORT.json` carries its hash.

Each warehouse family directory contains `family_manifest.json` and a `variants.csv` of the manifest's own fields (stem, target gap, measured gap, passable or blocked, certified).

A variant marked `refused` in `variants.csv` has no route XML: the generation pipeline validates every candidate scene in simulation before accepting it, and candidates that fail validation (for example, obstacle assets that tip over, roll away, or sink under physics) are refused rather than shipped. Refusals are retained in the catalog because they document the certified feasibility boundary of each family.

## Running the scenarios

See [docs/RUNNING.md](docs/RUNNING.md) for step-by-step instructions: CARLA setup, the harness environment, agent checkpoints, and the exact invocation. [docs/VERSIONS.md](docs/VERSIONS.md) pins every component we used, down to checkpoint revisions.

Short version, once CARLA 0.9.15 and the conda environment are up:

```bash
source env_vars.sh

python leaderboard/leaderboard/leaderboard_evaluator.py \
  --routes ${WORK_DIR}/scl_families/fm_001_intrusion_sweep/routes/Generalization_PassableObstacles_1060_001_intrusion_sweep_v01.xml \
  --agent <agent entry point> \
  --agent-config <checkpoint dir> \
  --track SENSORS \
  --traffic-manager-seed 0
```

## Bundled harness

The [Fail2Drive](https://github.com/autonomousvision/fail2drive) benchmark harness (Gerstenecker, Geiger and Renz, IROS 2026) is vendored in this repository at upstream commit `bceb18a`, under `leaderboard/`, `scenario_runner/`, `team_code/`, `toolbox/`, `tools/`, `assets/` and `fail2drive_split/`. Its own documentation - installation, the full Fail2Drive benchmark split, the SLURM evaluation tooling, the route-authoring toolbox - is unchanged and still applies. Upstream's README is preserved verbatim as [README.fail2drive.md](README.fail2drive.md) ([简体中文](README.fail2drive.zh-CN.md), [日本語](README.fail2drive.ja.md)) and is the reference for all of it; follow its installation section to build the conda environment and fetch the CARLA build.

Two fork patches are **already applied** to the vendored tree. Both are retained under `patches/` as a provenance record, so the exact deltas against upstream stay auditable:

1. `0001` - `AgentBlockedTest` `min_speed` 0.1 -> 0.2 m/s, in both the `leaderboard` and `scenario_runner` copies of `route_scenario.py`. A creeping agent (between 0.1 and 0.2 m/s) never triggers the 180 game-second blocked termination; with the patch, crawl-forever scores as blocked, the same as a full stop. **This is a scoring-semantics change: campaigns run across this boundary are not comparable.**
2. `0002` - `float()` the `CustomObstacle` actor sort key in `construction_crash_vehicle.py`. Fixes a `'<' not supported between instances of 'str' and 'int'` crash in scenarios mixing obstacles with and without an `x=` key.

Do not re-apply the patches; `git am patches/*.patch` against this tree will fail because the changes are already present.

## Measurement chain (`scl/`)

The tools that produced the paper's numbers live under [`scl/`](scl) as a generated, byte-identical export of the private pipeline's measurement layer: the scorers that read a campaign's runs, the boundary estimator, the certifiers, the pooling, the figure tools and the paper's render as one command, with the instruments, manifests, records and figure specs they read. [`scl/README.md`](scl/README.md) defines the vocabulary (campaign, raw and derived bundle, pin, chain, pool) and shows how to verify the export, verify a bundle against it, re-score a raw bundle and render the figures. `scl/PUBLIC_EXPORT.json` names the private commit and the hash of every file, `python3 verify_scl_export.py` from this directory checks the tree against it, and a derived campaign bundle's source manifest verifies against this tree. The August 2026 port under `analysis/` is retired by this export: it carried the positional collision attribution and the slope-capped estimator that the chain replaced in October 2026.

## Scope of this release

This release contains the ten scenario families, everything needed to run the seven driving families (the three warehouse families are published as manifests with catalogs; the Isaac Sim runner that compiles and runs them is not released), and the measurement chain under [`scl/`](scl). The raw campaign bundles (the simulator's evidence, 1.5 to 14 GB per campaign) are on the Hugging Face Hub at https://huggingface.co/datasets/socialchaoslab/failure-boundary-profiles-paper-campaigns, one zip per campaign with a sidecar file holding its content id, under CC BY 4.0; the scored bundles the records here pin are rebuilt from them with the chain under `scl/`, and every figure, table and number of the paper renders from the result. The scenario authoring system that generated these families is not part of this repository, nor are the driving agents' checkpoints (their authors' repositories hold them) or the warehouse runner.
